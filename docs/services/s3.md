# S3

**Status:** shipped

Lab-complete path-style S3: buckets and objects, bucket policies, SSE-S3/SSE-KMS, multipart upload, CopyObject (same account), bucket default encryption, versioning lite, and SigV4 query (presigned) GET/PUT.

## Implemented

| Area | Behavior |
|------|----------|
| Buckets | CreateBucket, DeleteBucket, ListBuckets, HeadBucket |
| Objects | PutObject (per-key lock; temp file then SQL then rename), GetObject, DeleteObject, HeadObject, ListObjectsV2 |
| Versioning | PutBucketVersioning / GetBucketVersioning (`Enabled` or `Suspended`), versioned Put/Get (`versionId`), ListObjectVersions lite |
| Bucket policy | PutBucketPolicy, GetBucketPolicy, DeleteBucketPolicy |
| Notifications | PutBucketNotificationConfiguration / GetBucketNotificationConfiguration (`?notification`). Lambda, SQS, SNS topic, and EventBridgeConfiguration CRUD with destination existence and resource-policy checks (`s3.amazonaws.com` + `aws:SourceArn` bucket ARN). Empty config is the default (notifications off). On successful PutObject / DeleteObject / CompleteMultipartUpload, matching destinations are delivered best-effort: Lambda async invoke, SQS SendMessage, EventBridge PutEvents (`source=aws.s3`), SNS Publish (HTTP subscribers stay allowlist/catcher-only). Emit re-checks destination authz (not an open proxy) |
| Multipart | CreateMultipartUpload, UploadPart, CompleteMultipartUpload, AbortMultipartUpload, ListParts, ListMultipartUploads (non-final parts must be at least 5 MiB on Complete, matching AWS `EntityTooSmall`) |
| Copy | CopyObject (same account, server-side copy) |
| Encryption | SSE-S3 (`AES256`) and SSE-KMS (`aws:kms`) on Put/Get (per-request SSE headers). SSE-KMS seals the object DEK with EncryptionContext `aws:s3:arn` = object ARN. Optional `x-amz-server-side-encryption-context` (base64 JSON string pairs) merges into that map; customer pairs are persisted with the object and rebuilt on Get/Copy/multipart Complete for authorize + decrypt |
| Bucket encryption | PutBucketEncryption, GetBucketEncryption, DeleteBucketEncryption (default SSE inheritance on Put when request omits SSE headers) |
| Addressing | Path-style only |
| Presign | Query SigV4 GET/PUT (`X-Amz-Expires` max 604800) |
| Anonymous Get | Opt-in only: `NOCTAXRIS_ALLOW_ANONYMOUS_S3=1` plus bucket policy `Principal: "*"` / `{"AWS":"*"}` Allow on `s3:GetObject`, or object canned ACL `public-read` / `public-read-write` via `x-amz-acl` on PutObject. Default Compose leaves the env unset. Unsigned List/Put and other S3 APIs stay SigV4-required. SSE-KMS objects still need a principal that can `kms:Decrypt` (anonymous fails closed). |

Object bytes live under `$DATAROOT/s3/{account}/{bucket}/...`. Bucket and object metadata live in SQLite. SSE-S3 DEKs are sealed with the data-root master key. SSE-KMS uses KMS GenerateDataKey / Decrypt under the caller.

### Authz notes

S3 uses `EvaluateS3` with the bucket owner account from store metadata. Same-account access: allow if identity **or** bucket policy Allows. Cross-account access: allow only when identity **and** bucket policy both Allow (empty bucket policy denies cross-account callers). Explicit Deny in either wins. Org SCP/RCP filters apply before evaluation. When identity Allows, permissions boundary and session intersect. `PutBucketPolicy` requires every statement to name a `Principal` (missing Principal is rejected at put and would match-none at eval).

Unsigned `GetObject` / `HeadObject` are off by default (PublicAccessBlock-shaped). With `NOCTAXRIS_ALLOW_ANONYMOUS_S3=1`, the pre-SigV4 gate evaluates only path-style object GET/HEAD against `EvaluateAnonymousS3GetObject`: bucket policy Allow for Principal `"*"` / `{"AWS":"*"}`, or object canned ACL `public-read` / `public-read-write`. Explicit Deny in the bucket policy wins over ACL. The gate does not skip SigV4 for List/Put or other S3 APIs.

## How to verify / CLI smoke

Shared Compose and env setup: [index.md](index.md#shared-verification). Force path-style addressing for the local endpoint. For SSE-KMS, create a key first ([kms.md](kms.md)).

```bash
aws configure set default.s3.addressing_style path

BUCKET="noctaxris-lab-$RANDOM"
aws s3 mb "s3://$BUCKET" --endpoint-url "$EP"
echo hello-s3 > /tmp/noctaxris-obj.txt
aws s3 cp /tmp/noctaxris-obj.txt "s3://$BUCKET/hello.txt" --endpoint-url "$EP"
aws s3 ls "s3://$BUCKET" --endpoint-url "$EP"
aws s3 cp "s3://$BUCKET/hello.txt" /tmp/noctaxris-obj-out.txt --endpoint-url "$EP"

# SSE-S3
aws s3 cp /tmp/noctaxris-obj.txt "s3://$BUCKET/sse-s3.txt" \
  --sse AES256 --endpoint-url "$EP"

# SSE-KMS (KEY_ID from kms create-key)
aws s3 cp /tmp/noctaxris-obj.txt "s3://$BUCKET/sse-kms.txt" \
  --sse aws:kms --sse-kms-key-id "$KEY_ID" --endpoint-url "$EP"

# Presign then curl (query SigV4, no Authorization header)
URL=$(aws s3 "presign" "s3://$BUCKET/hello.txt" --endpoint-url "$EP")
curl -fsS "$URL"
```

Multipart and bucket encryption:

```bash
BUCKET="noctaxris-mp-$RANDOM"
aws s3api create-bucket --bucket "$BUCKET" --endpoint-url "$EP"
aws s3api put-bucket-encryption --bucket "$BUCKET" --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}' --endpoint-url "$EP"
```

Two-account cross-account read (member account B owns the bucket, member account A user reads via dual eval):

```bash
# Account B: create bucket, object, and bucket policy allowing account A principal
aws s3 mb "s3://$BUCKET" --endpoint-url "$EP" --profile account-b
echo hello-xa > /tmp/xa-obj.txt
aws s3 cp /tmp/xa-obj.txt "s3://$BUCKET/xa.txt" --endpoint-url "$EP" --profile account-b
aws s3api put-bucket-policy --bucket "$BUCKET" --endpoint-url "$EP" --profile account-b \
  --policy '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::ACCOUNT_A:user/reader"},"Action":"s3:GetObject","Resource":"arn:aws:s3:::'"$BUCKET"'/*"}]}'

# Account A: identity policy plus bucket policy must both Allow
aws s3 cp "s3://$BUCKET/xa.txt" /tmp/xa-out.txt --endpoint-url "$EP" --profile account-a
```

## How to verify / anonymous GetObject (opt-in)

Requires `NOCTAXRIS_ALLOW_ANONYMOUS_S3=1` on the API process (not set in default Compose). Then either a public bucket policy or `x-amz-acl: public-read` on the object:

```bash
export NOCTAXRIS_ALLOW_ANONYMOUS_S3=1
# restart API / Compose with that env, then:
aws s3api put-bucket-policy --bucket "$BUCKET" --endpoint-url "$EP" --policy \
  '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":"*","Action":"s3:GetObject","Resource":"arn:aws:s3:::'"$BUCKET"'/*"}]}'
curl -fsS "http://127.0.0.1:4566/$BUCKET/hello.txt"
```

Without the env flag, the same policy still requires SigV4 (`MissingAuthenticationToken` on unsigned GET).

## How to verify / bucket notifications

Destinations need a resource policy Allow for `s3.amazonaws.com` with `aws:SourceArn` matching the bucket ARN (Lambda: `AddPermission`; SQS: queue `Policy`). Empty notification config means PutObject does not emit.

```bash
BUCKET="noctaxris-notify-$RANDOM"
QUEUE="noctaxris-notify-q-$RANDOM"
aws s3api create-bucket --bucket "$BUCKET" --endpoint-url "$EP"
QUEUE_URL=$(aws sqs create-queue --queue-name "$QUEUE" --endpoint-url "$EP" --query QueueUrl --output text)
QUEUE_ARN=$(aws sqs get-queue-attributes --queue-url "$QUEUE_URL" --attribute-names QueueArn --endpoint-url "$EP" --query Attributes.QueueArn --output text)
aws sqs set-queue-attributes --queue-url "$QUEUE_URL" --endpoint-url "$EP" --attributes "Policy={\"Version\":\"2012-10-17\",\"Statement\":[{\"Effect\":\"Allow\",\"Principal\":{\"Service\":\"s3.amazonaws.com\"},\"Action\":\"sqs:SendMessage\",\"Resource\":\"$QUEUE_ARN\",\"Condition\":{\"ArnLike\":{\"aws:SourceArn\":\"arn:aws:s3:::$BUCKET\"}}}]}"
aws s3api put-bucket-notification-configuration --bucket "$BUCKET" \
  --notification-configuration "{\"QueueConfigurations\":[{\"QueueArn\":\"$QUEUE_ARN\",\"Events\":[\"s3:ObjectCreated:*\"]}]}" \
  --endpoint-url "$EP"
echo hi > /tmp/noctaxris-notify.txt
aws s3 cp /tmp/noctaxris-notify.txt "s3://$BUCKET/hi.txt" --endpoint-url "$EP"
aws sqs receive-message --queue-url "$QUEUE_URL" --endpoint-url "$EP"
```
