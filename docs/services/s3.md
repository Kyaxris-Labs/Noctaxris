# S3

**Status:** shipped

Lab-complete path-style S3: buckets and objects, bucket policies, SSE-S3/SSE-KMS, multipart upload, CopyObject (same account), bucket default encryption, versioning lite, and SigV4 query (presigned) GET/PUT.

## Implemented

| Area | Behavior |
|------|----------|
| Buckets | CreateBucket, DeleteBucket, ListBuckets, HeadBucket |
| Objects | PutObject (per-key lock; temp file then SQL then rename), GetObject, DeleteObject, HeadObject, ListObjectsV2 |
| Versioning | PutBucketVersioning / GetBucketVersioning (`Enabled` or `Suspended`), versioned Put/Get (`versionId`), ListObjectVersions lite |
| Bucket policy | PutBucketPolicy, GetBucketPolicy, DeleteBucketPolicy |
| Multipart | CreateMultipartUpload, UploadPart, CompleteMultipartUpload, AbortMultipartUpload, ListParts, ListMultipartUploads (non-final parts must be at least 5 MiB on Complete, matching AWS `EntityTooSmall`) |
| Copy | CopyObject (same account, server-side copy) |
| Encryption | SSE-S3 (`AES256`) and SSE-KMS (`aws:kms`) on Put/Get (per-request SSE headers) |
| Bucket encryption | PutBucketEncryption, GetBucketEncryption, DeleteBucketEncryption (default SSE inheritance on Put when request omits SSE headers) |
| Addressing | Path-style only |
| Presign | Query SigV4 GET/PUT (`X-Amz-Expires` max 604800) |

Object bytes live under `$DATAROOT/s3/{account}/{bucket}/...`. Bucket and object metadata live in SQLite. SSE-S3 DEKs are sealed with the data-root master key. SSE-KMS uses KMS GenerateDataKey / Decrypt under the caller.

### Authz notes

S3 uses `EvaluateS3` with the bucket owner account from store metadata. Same-account access: allow if identity **or** bucket policy Allows. Cross-account access: allow only when identity **and** bucket policy both Allow (empty bucket policy denies cross-account callers). Explicit Deny in either wins. Org SCP/RCP filters apply before evaluation. When identity Allows, permissions boundary and session intersect.

## How to verify / CLI smoke

Shared Compose and env setup: [index.md](index.md#shared-verification). Force path-style addressing for the local endpoint. For SSE-KMS, create a key first ([kms.md](kms.md)).

```bash
aws configure set default.s3.addressing_style path

BUCKET="noctaxris-lab-$RANDOM"
aws s3 mb "s3://$BUCKET" --endpoint-url "$EP"
echo hello-s3 > /tmp/noctaxris-obj.txt
aws s3 cp /tmp/noctaxris-obj.txt "s3://$BUCKET/hello.txt" --endpoint-url "$EP"
aws s3 ls "s3://$BUCKET" --endpoint-url "$EP"
aws s3 cp "s3://$BUCKET/hello.txt" /tmp/noctaxris-obj-out.txt --endpoint-url "$EP"

# SSE-S3
aws s3 cp /tmp/noctaxris-obj.txt "s3://$BUCKET/sse-s3.txt" \
  --sse AES256 --endpoint-url "$EP"

# SSE-KMS (KEY_ID from kms create-key)
aws s3 cp /tmp/noctaxris-obj.txt "s3://$BUCKET/sse-kms.txt" \
  --sse aws:kms --sse-kms-key-id "$KEY_ID" --endpoint-url "$EP"

# Presign then curl (query SigV4, no Authorization header)
URL=$(aws s3 "presign" "s3://$BUCKET/hello.txt" --endpoint-url "$EP")
curl -fsS "$URL"
```

Multipart and bucket encryption:

```bash
BUCKET="noctaxris-mp-$RANDOM"
aws s3api create-bucket --bucket "$BUCKET" --endpoint-url "$EP"
aws s3api put-bucket-encryption --bucket "$BUCKET" --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}' --endpoint-url "$EP"
```

Two-account cross-account read (member account B owns the bucket, member account A user reads via dual eval):

```bash
# Account B: create bucket, object, and bucket policy allowing account A principal
aws s3 mb "s3://$BUCKET" --endpoint-url "$EP" --profile account-b
echo hello-xa > /tmp/xa-obj.txt
aws s3 cp /tmp/xa-obj.txt "s3://$BUCKET/xa.txt" --endpoint-url "$EP" --profile account-b
aws s3api put-bucket-policy --bucket "$BUCKET" --endpoint-url "$EP" --profile account-b \
  --policy '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::ACCOUNT_A:user/reader"},"Action":"s3:GetObject","Resource":"arn:aws:s3:::'"$BUCKET"'/*"}]}'

# Account A: identity policy plus bucket policy must both Allow
aws s3 cp "s3://$BUCKET/xa.txt" /tmp/xa-out.txt --endpoint-url "$EP" --profile account-a
```

A later opt-in must stay default-deny (for example explicit env gate plus bucket policy `Principal: "*"` Allow, and PublicAccessBlock-shaped controls) so open buckets cannot appear by accident on the published listener.

- Full S3 SAR beyond the lab set (lifecycle, CORS, website, Object Lock, replication, access points, inventory, Select, Glacier, tagging APIs beyond basics, ACLs beyond default private, delete markers depth)
- Virtual-hosted-style endpoints and Transfer Acceleration
- S3 ACL cross-account and access points
